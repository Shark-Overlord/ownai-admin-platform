# 项目执行规则

## 开始前
- 按钮和文字最大不超过16px 标题除外  一般是14ox
- 每次开始执行当前项目任务前，必须先阅读本文件，再进行搜索、修改或验证。
- 默认优先处理前端相关任务，保持现有视觉风格和代码结构，不主动做大范围重构。
- 修改前先阅读相关组件、页面和依赖文件，避免凭猜测直接改动。

## 改动原则
- 只做完成当前任务所必需的最小改动。
- 优先复用现有组件、工具函数、hooks、样式变量和交互模式。
- 涉及界面修改时，同时兼顾桌面端与移动端表现和基本可访问性。

## Prompt 产品默认假设
- 本项目默认产品方向是面向设计师与开发者的中文优先 Prompt 会员库，英文能力作为未来国际化升级预留。
- 默认业务路线是“单条 Prompt 浏览 + 会员解锁全文”，不默认扩展为在线生成 SaaS。
- 默认商业模式以会员订阅为主，不默认做单条 Prompt 单买。
- 默认保持当前 React + Vite + TypeScript 前端骨架和现有视觉风格。
- 默认中文内容和词条需要完整跟进；英文不是当前每次交付的必备项，除非用户明确要求或现有功能已经依赖多语言结构。

## Prompt 产品方向规则
- 核心目标是提升 Prompt 的浏览、检索、复制和会员转化效率。
- 默认优先建设 Prompt 列表、Prompt 详情、会员权益展示、登录后解锁与收藏能力。
- 未经用户明确要求，不新增单品购物车、复杂结算流、积分商城、社区发帖、聊天式工作台等重功能模块。
- 允许短期复用现有内容流和会员下单骨架，但整体产品语义应逐步从 `site / artwork / project` 过渡到 `prompt / collection / membership access`。

## 信息架构规则
- 首页首屏必须清楚表达目标人群、会员价值、可获得的 Prompt 类型，以及为什么值得订阅。
- 列表页和卡片优先展示任务场景、适用角色、兼容模型、标签、预览摘要、解锁状态，不以大图展示为主。
- 分类和筛选优先围绕任务类型、角色、模型、难度、语言、更新时间，不沿用泛灵感站的视觉风格分类作为主轴。
- 单条 Prompt 应优先有详情页承接，列表页只展示预览，不直接堆满完整 Prompt 正文。
- 现有 `Projects` 相关能力，如无明确要求，默认向“收藏夹 / 我的 Prompt / 我的合集”方向演进，不继续扩展为文件上传工作台。

## Prompt 内容建模规则
- 新增或调整前端类型、接口映射、组件命名时，默认使用 Prompt 语义，如 `PromptItem`、`PromptDetail`、`PromptPreview`、`MembershipEntitlement`。
- 单条 Prompt 默认应包含：标题、适用场景、目标角色、兼容模型、预览内容、完整内容、输出示例、标签、语言、访问权限、更新时间。
- 允许短期复用现有 `artwork / site` 接口字段做映射，但新增页面和新增变量命名应避免继续扩大 `site`、`artwork`、`project` 这些偏题语义。
- 如果新增公开类型或接口，至少覆盖 `PromptItem`、`PromptDetail`、`PromptAccessState`、`PromptLanguage`、`PromptModelCompatibility` 这类语义。
- 与会员权限相关的前端状态机至少覆盖：访客、已登录免费用户、会员用户、接口异常回退。
- 涉及权限展示时，必须区分未登录、已登录未开通会员、已开通会员三种状态，避免只做简单禁用按钮。

## 会员转化规则
- 本项目默认以会员订阅为主要商业模式，页面文案与交互优先突出会员权益、更新频率、可解锁内容范围、复制/收藏权限，不默认突出单品购买。
- Pricing 页面优先解释不同会员层级能解锁哪些 Prompt、适合哪些用户、更新频率和使用场景，而不是只展示价格数字。
- 被锁定的 Prompt 必须提供足够的预览价值和升级入口，避免出现“看不到内容也不知道值不值得买”的死挡板。
- 登录后的主要动作优先是复制 Prompt、收藏 Prompt、升级会员，不默认增加与产品方向无关的工作台入口。

## 双语与文案规则
- 新增用户可见文案优先保证中文完整、准确、可用；英文为未来升级和国际化预留空间，不作为当前每次新增 UI 的硬性必备项。
- 如果当前组件或页面已经采用 `zh-CN` / `en-US` 结构，修改时尽量保持结构不被破坏，可补充简洁英文占位；没有现成多语言结构时，不为了英文预留而扩大改动范围。
- 涉及 Prompt 标题、摘要、标签时，优先保证中文检索可读性、专业术语准确性和用户理解效率；英文只在明确需要时补充等价表达，不做机械直译。

## 前端实现与视觉规则
- 保持现有简洁、排版驱动、轻量高级感的视觉语言，不主动改成厚重后台、复杂图表面板或泛 AI 产品模板风格。
- 视觉设计优先符合主流产品审美和真实使用效率，避免小众、实验性或过度装饰的样式抢占内容注意力。
- 涉及界面修改时必须同时考虑深色模式与浅色模式；颜色优先使用现有 CSS 变量或设计令牌，避免只在单一主题下看起来正常。
- Prompt 卡片和详情页优先保证信息密度、可扫描性、复制效率和移动端可读性，避免过强装饰性插画挤占关键信息。
- 移动端样式需要同步考虑布局、点击面积、文字换行、浮层位置和滚动体验，不能只按桌面端效果推断移动端可用。
- 修改时优先复用现有 Navbar、Filter、Card、Pricing 结构，做小而准确的改造，不主动做全站重构。
- 保持基本可访问性，特别是键盘可操作、复制按钮焦点态、筛选器可读标签、移动端 CTA 点击面积。
- 调整按钮字号时，不能只改外层 `button` 的字号类；必须同时检查按钮内部的 `span`、`p`、图标旁文本节点是否单独承载视觉字号，必要时直接给内部文字节点显式设置字号。
- 遇到“按钮看起来没变小/没变大”的情况，优先排查 3 点：内部文本节点是否有独立字号、是否存在组件/全局 `!important` 规则、按钮高度和 padding 是否掩盖了字号变化。
- 涉及按钮字体调整时，默认把按钮高度、padding、图标尺寸、内部文字字号一起联动检查，不要只改一层 class 后就认为已经生效。
- 成功或失败反馈默认使用组件化的 `message` / toast 提示，不要在页面内容区插入大块横向提示条；尤其是收藏、取消收藏、复制、刷新这类即时操作，应避免出现占位很高、影响列表布局的内嵌提示信息。
- 成功、失败、校验、加载失败这类短提示文案末尾不要带句号、中文句号、省略号或感叹号，保持简短干净；正文说明、协议条款和营销描述不受此限制。

## 用户菜单规则
- 右上角个人信息悬浮菜单优先保持紧凑，不要做过大的弹框和过高的按钮。
- 个人信息悬浮菜单里不要重复放 Navbar 的导航路径项。
- 如果设置页尚未实现，优先放 `Settings` 作为占位入口。
- `Logout / Sign out` 操作始终使用红色强调样式。

## 验证要求
- 能做验证时，优先运行最小必要范围的检查、测试或构建命令。
- 涉及 Prompt 会员库方向的改动，优先验证首页浏览、筛选搜索、Prompt 锁定态、登录跳转、会员升级入口、深色/浅色主题和移动端显示；多语言/英文只在本次改动实际涉及时验证。
- 重点检查 Prompt 列表卡片是否清楚展示场景、模型、标签、预览和锁定态，避免退化成纯灵感站卡片。
- 验证未登录用户点击受限内容是否正确引导登录，已登录非会员是否引导升级，会员是否可正常复制全文。
- 验证 Pricing 页面是否突出会员权益说明，而不是退化成纯价格墙。
- 未经用户授权，不允许擅自重置数据库或删除数据库中已有的数据。
- 如果没有运行验证，必须明确说明原因。
-禁止出现以下问题：
- 超大按钮
- 巨型搜索框
- Dribbble 风格的夸张视觉
- 按钮高度 >= 44px
- 按钮宽度无意义过长
- 一个区域多个高强调色按钮
- 过重阴影
- 过大的圆角（如 rounded-2xl / rounded-full 大量滥用）
- 移动端风格误用到桌面端后台页面
