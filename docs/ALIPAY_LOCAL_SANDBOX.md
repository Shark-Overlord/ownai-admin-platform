# Alipay Computer Website Payment: Local Sandbox Setup

This project uses Alipay Computer Website Payment (`alipay.trade.page.pay`) for one-time member purchases.
It does not use subscription billing and does not activate a membership from the browser return page.

## 1. What must be prepared in Alipay

In the Alipay sandbox application, enable Computer Website Payment and use the sandbox values below:

| Runtime variable | Where it comes from | Important note |
| --- | --- | --- |
| `ALIPAY_APP_ID` | Sandbox application App ID | Do not use the production App ID for local testing. |
| `ALIPAY_APP_PRIVATE_KEY` | The application private key generated by the merchant | This is the private key. Never commit it or send it in a ticket/chat. |
| `ALIPAY_PUBLIC_KEY` | Alipay sandbox public key | This is Alipay's public key, not the merchant application's public key. |
| `ALIPAY_GATEWAY_URL` | Sandbox gateway | `https://openapi-sandbox.dl.alipaydev.com/gateway.do` |

The application signature setting is required. Keep **interface content encryption disabled** for this integration. The
current service uses RSA2 request signing and signature verification; it intentionally does not accept or store an AES
content-encryption key. Enabling content encryption in the Alipay console without implementing it in the SDK client can
make gateway responses unreadable.

## 2. Start a temporary public callback tunnel

Alipay cannot call `127.0.0.1` for asynchronous notifications. Start a temporary Cloudflare quick tunnel in a separate PowerShell window:

```powershell
cloudflared tunnel --url http://127.0.0.1:8011
```

Copy the generated `https://...trycloudflare.com` URL. The notification URL must be:

```text
https://YOUR-TUNNEL.trycloudflare.com/api/payment/alipay/notify
```

Configure this same value as the application's **Application Gateway** in the Alipay sandbox console. The browser
return URL is a separate endpoint and must also be publicly reachable:

```text
https://YOUR-TUNNEL.trycloudflare.com/api/payment/alipay/return
```

Keep that terminal open during the full payment test. A quick tunnel URL changes each time it is restarted.

## 3. Set local environment variables

Open the PowerShell window that starts the Spring Boot backend. Replace every placeholder locally. Do not save real values to YAML files or Git.

```powershell
$env:ALIPAY_ENABLED = "true"
$env:ALIPAY_APP_ID = "YOUR_SANDBOX_APP_ID"
$env:ALIPAY_APP_PRIVATE_KEY = "YOUR_MERCHANT_APPLICATION_PRIVATE_KEY"
$env:ALIPAY_PUBLIC_KEY = "YOUR_ALIPAY_SANDBOX_PUBLIC_KEY"
$env:ALIPAY_GATEWAY_URL = "https://openapi-sandbox.dl.alipaydev.com/gateway.do"
$env:ALIPAY_NOTIFY_URL = "https://YOUR-TUNNEL.trycloudflare.com/api/payment/alipay/notify"
$env:ALIPAY_RETURN_URL = "https://YOUR-TUNNEL.trycloudflare.com/api/payment/alipay/return"
$env:ALIPAY_FRONTEND_RETURN_URL = "http://127.0.0.1:5173/#/pricing/payment-result"
$env:ALIPAY_PENDING_ORDER_TIMEOUT_MINUTES = "15"
```

If keys were copied as PEM blocks, PowerShell can preserve the line breaks with a here-string. The backend removes PEM headers and whitespace at runtime:

```powershell
$env:ALIPAY_APP_PRIVATE_KEY = @'
-----BEGIN PRIVATE KEY-----
PASTE_KEY_HERE
-----END PRIVATE KEY-----
'@
```

Restart the backend after setting the variables:

```powershell
cd E:\JAVA_project\springboot-init-master
.\mvnw.cmd spring-boot:run "-Dspring-boot.run.profiles=local"
```

## 4. Test flow

1. Sign in to the local frontend at `http://127.0.0.1:5173/#/pricing`.
2. Choose a plan. The frontend sends only `planType` and a browser-generated `requestId`; the server uses the database price.
3. The browser submits the server-generated, signed Alipay HTML form with `POST` and opens the Alipay sandbox cashier.
   Do not convert this form to a query-string URL or open it with a browser `GET` request.
4. Alipay calls `POST /api/payment/alipay/notify` through the tunnel. The server verifies its signature, then queries Alipay again before completing the order.
5. Alipay returns the browser to `/api/payment/alipay/return` through the tunnel. The server verifies that signed return,
   refreshes the order from Alipay, then redirects to the local frontend result page with the order number.
6. The browser result page polls `GET /api/member/payment/status?orderNo=...` and shows the completed result.
7. Check `member_order`: the order should be `completed`, have `paymentChannel=alipay`, and record the Alipay trade number. The user should have `memberLevel=member`.

## 5. Safety rules implemented by the backend

- `paymentRequestId` is unique per user, so browser retries reuse one pending order.
- The backend ignores frontend amounts and reads the active plan price from `member_price_config`.
- A callback must pass RSA2 signature verification, match the configured `app_id`, and pass an active `alipay.trade.query` amount and success-status check.
- Duplicate callbacks are idempotent: a completed order is not activated twice.
- Pending Alipay orders are queried and closed after 15 minutes. The server checks Alipay before marking them expired.
- The browser return URL is display-only. It verifies the signed parameters and refreshes provider state, but cannot grant
  membership from browser-provided parameters alone.

## 6. Production later

Use the production App ID, production Alipay public key, `https://openapi.alipay.com/gateway.do`, and a stable HTTPS notification endpoint on `admin.ownai.icu` or a dedicated payment subdomain. Configure the same values as server environment variables, then restart the production backend. Do not use a temporary tunnel in production.
